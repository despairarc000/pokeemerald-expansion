# Diary 02 (logs 11 to 22)

The story of the project in order. Short on purpose. Dates are by session. For the routine, see `ONBOARDING.md`. Earlier history is in `diary01.md`.

## Log 11: The world should feel real (2026-11-05)
The owner clarified what "free exploration" means for the map: the world should feel like the real world, not like Pokemon-coded maps. Terrain restricts movement because of what it is (a dense forest is slow, a waterfall drop is insane), never to guide or gate the player. We recorded this as "world feel rules" in `features/regions-and-exploration.md`: barriers are costs, not locks, no cut-tree or boulder gates, paths follow valleys and rivers, settlements sit where people would live. The mainland is continuous, with natural barriers that cost something.

## Log 12: Fix shared-edge map connection boundary (2026-11-06)
The owner asked to fix the Emerald engine's off-by-one connection lookup directly on `master`, without a branch, so it would not be forgotten during mobile map-editor work. In `src/fieldmap.c`, `IsCoordInIncomingConnectingMap` now treats the upper bound as exclusive (`coord < max`), matching the engine's other connection range check. Example: a 10-high map with two 5-high neighbors on the right now selects the first for rows 0–4 and the second for rows 5–9 without double-matching row 5. Engine commit: `eeec45dc613d8486c3cf1639619ce8e1a9f466a6`. Boundary-case logic was checked; native build and emulator behavior are **not yet verified**. This direct-to-master engine fix was an explicit owner-requested exception to the usual branch rule.

## Log 13: The AI becomes the author, and the pipeline (2026-11-06)
The owner made the AI the author of the lore and of the look and feel of each region, and said they want to experience the world as a player. The AI keeps new lore out of the chat. The first Keepers draft was already shown, so it is spoiled and may change. For maps, we chose a text-grid approach: `tools/textmap/build_textmaps.py` turns a text map into the engine's binary data during the build, and a first test map was added. The pull request was merged by the owner about 11 minutes after opening, with no CI checks recorded, so **the pipeline is on `master` untested**. The AI cannot write binary files, so new tiles will be generated elsewhere (ChatGPT), and the owner and ChatGPT are building a separate map maker.

## Log 14: Meadowmere designed down to the natural maps (2026-11-06)
At a high level the AI wrote the region brief, then the seven areas, the four main places plus nineteen smaller ones, and 28 interiors. The owner chose to do natural lands and waters first, with no houses or buildings. The AI then designed 20 natural maps (tile roles instead of tile ids, size classes, exits, terrain mix, wildlife behavior, curiosity-slot counts) with reserved gaps where villages will sit. The owner confirmed that natural lands and waters are done. Villages, species per zone, curiosity contents and real tiles are not part of that step.

## Log 15: Next regions stay shallow (2026-11-06)
The owner decided that from here on each region is designed only as natural lands and waters, and only coarsely, so that a revision does not waste effort on intricate detail. No places, interiors or per-map terrain percentages for now. Mistvale was done this way: a region brief, six areas, and a coarse list of 17 natural maps (name, size, danger, one line) in `design/region-mistvale.md`. The depth of Meadowmere stays as the reference for how deep a region can later go.

## Log 16: Map Studio Rust APK design consolidated (2026-11-07)
The owner asked for a final review before implementation of the Android map maker. We selected a native Rust approach (eframe/egui with wgpu), retaining the HTML v3 UI as visual reference, with one Rust model for editing, autosave, AI commands and real Emerald export. The implementation baseline is `design/map-studio-implementation.md`: first prove a minimal APK on the phone, then the canvas, actual tilesets, native export and transitions. GitHub snapshot collaboration precedes a possible hosted live service. Known uncertainties—device performance, untested native export, and the engine's unsafe small-map neighbor copying—remain tests, not completed features. **No APK code, service or ROM build was produced in this session.**

## Log 17: First native Map Studio APK compiled (2026-11-07)
The owner explicitly initiated implementation of the native Rust map maker. The first working code is on branch `feature/map-studio-native-android` under `tools/map-studio/`: `eframe`/`egui` with `wgpu`, a white grid, three gray adjoining frames, provisional color-tile painting, collision overlays, event markers and touch pan/pinch UI. The pure Rust world model prevents map overlap, packs Emerald collision/elevation fields and calculates shared-edge connections. GitHub Actions run `42319371555` passed its Rust unit tests, desktop compile and ARM64 Android APK packaging; downloadable artifact `map-studio-arm64-debug` is available in that run. This is **not device-tested**: launch, touchscreen behavior, performance and lifecycle handling remain unverified. The tiles are placeholders, and the app does not yet support persistent saves, actual tilesets, GBA export, GitHub synchronization, or live collaboration.

## Log 18: Map Studio optimized Android test APK (2026-11-07)
The owner asked to shrink the 228 MiB native Rust debug APK. On branch `feature/map-studio-native-android` the `Cargo.toml` release profile now enables size optimization, LTO, single codegen unit, symbol stripping and abort-on-panic; its Android CI workflow produces a temporarily signed ARM64 release APK. Run `42322214875` passed both the Rust desktop/tests job and the optimized Android packaging job. Downloaded `map-studio.apk` was checked: 3,273,066 bytes (3.12 MiB) versus the previous 238,711,146 bytes (227.65 MiB), a 98.63% size reduction. The APK archive passed integrity checking and the JAR signature verified (self-signed test certificate). **Device startup, touch UI and real map export remain untested.** Test signing keys are ephemeral per CI run, so an earlier APK may need uninstalling before installing another.

## Log 19: Map Studio native map compiler, backup and CLI milestone (2026-11-07)
The owner confirmed that the small Rust APK launches and its canvas is usable on an Android phone, then requested continued implementation. Work is isolated on branch `feature/map-studio-native-android`. Map Studio now includes actual General/Petalburg metatile atlas graphics, offline JSON autosave, undo/redo, map frame geometry/renaming/deletion, basic typed events and NPC/sign scripts, collision/elevation editing, and Rust numeric map ZIP export through the existing custom-map generator. New Android JNI integration publishes **Backup JSON** and validated **Export ZIP** into user-accessible Downloads/MapStudio on Android 10+. The headless `map-studio-cli` can create/paint/validate/export projects, enabling AI to modify the same format outside the UI. Run `42325908716` passed Rust tests, cross-language export through `tools/textmap/build_textmaps.py`, desktop checks and optimized ARM64 APK packaging; the APK was independently checked as a valid signed archive (about 3.4 MiB). **Critical limits:** only the earlier prototype launch is device-confirmed; Downloads integration in this APK, produced maps in a running GBA ROM, secure GitHub sync and live AI collaboration are not yet field-tested or implemented. The existing small-map camera buffer issue remains separate. Main-game source logic was not changed.

## Log 20: Map Studio v0.4 UX improvements and side-by-side preview (2026-11-07)
After testing an earlier native APK on Android, the owner requested automatic empty-canvas panning, exact map dimensions and four expansion directions, clearer collision and elevation editing, and better tap/double-tap event interaction. On branch `feature/map-studio-native-android`, Rust now handles free drag-to-pan on blank canvas, explicit +Map with exact width/height and expansion toward upper-left/upper-right/lower-left/lower-right, safe direction-aware resizing that preserves global occupied cell/event positions, a Fit command, clearer C0–C3 collision and E0–E15 elevation overlays with selected-cell readout, and compact tap-to-select/type-switch/double-tap event controls. The CLI supports the same anchored geometry, and new projects open on a blank canvas. Tests include all corner expansions, collision/elevation bit correctness, preservation of map data, headless CLI, and native Emerald generator conversion.

GitHub Actions run `42328590131` **passed** Rust model/CLI tests, desktop UI compile, and ARM64 APK packaging. The signed, ZIP-verified APK is 3,584,362 bytes (3.42 MiB). The new APK has separate Android package `dev.despairarc.mapstudio.preview` (label **Map Studio Preview**) so installing it does not require removing the older package `dev.despairarc.mapstudio`; save data is *not* shared between the two. Preview signing keys remain disposable. **No physical-device test of this new UI version or full GBA ROM/emulator playtest has been completed.** Secure GitHub synchronization, generic project import, stable release signing, and live AI collaboration are not yet implemented.

## Log 21: Map Studio v0.5 native project restoration milestone (2026-11-07)
The owner requested further implementation after v0.4. On `feature/map-studio-native-android`, the Rust editor now has a Project menu for New / Backup / Restore / Export. Android MediaStore integration can list and read *this app's own* Downloads/MapStudio JSON backup files and map-export ZIPs; the desktop app also sees local recovery files. Versioned project decoding has a 20 MiB safety cap and validates map geometry, cells, events and schema before allowing replacement. Every New/Restore action writes a recovery copy of the previous canvas before saving the replacement, and resets UI selections/history. Game-source ZIPs can be restored by decoding the embedded `mapstudio-project.json` without extracting files. The headless `map-studio-cli` likewise supports safe `import` / `restore` with recovery snapshots.

GitHub Actions run `42329689310` passed Rust unit tests (including import-restore safety), CLI geometry and Rust-to-Python map export checks, desktop compile and optimized ARM64 APK packaging. The checked, self-signed APK is 3,641,706 bytes (about 3.47 MiB) under package `dev.despairarc.mapstudio.preview`. **Only automated tests passed; Android device restore UI/MediaStore access in this build has not yet been physically tested.** This is not a generic Storage Access Framework picker: backups created by another package may not be visible. The Preview still uses ephemeral test signing per CI run. Full ROM emulator proof and secure GitHub/live AI collaboration remain unfinished; do not conflate local backup browsing with cloud synchronization.

## Log 22: Map Studio touch-first UX after owner device feedback (2026-11-07)
Owner reported that v0.5 made map creation harder, requested the original long-press rectangle drawing and automatic map movement, a draggable/resizable bottom palette, original numeric collision indicators and behavior icons, elevation choices rather than a slider, and no arbitrary technical IDs for NPCs. Researched established Tiled/Porymap rectangle, layer/property and event conventions plus Android bottom-sheet drag-handle guidelines. On `feature/map-studio-native-android` these are implemented in native egui: hold on blank grid ~0.46s then drag to create, with visible valid/invalid rectangle and immediate overlap warning; quick drag on blank grid pans; hold map then slide moves it with no collision overlap; Size panel previews invalid directional expansions **before** Apply; 38-pixel visible dock handle adjusts responsive palette height. The Properties panel again shows collision values `0`–`3`, data-driven `~`/snowflake/ledge arrows from the actual General/Petalburg metatile attribute binaries, and a discrete 4×4 elevation grid. NPC choices are vetted from the real `event_objects.h` symbols but displayed as friendly names, with no free-form graphics identifier; NPC/sign dialogues now start empty and prohibit invalid script characters. Warp/trigger creation and authoring are intentionally deferred.

GitHub Actions `42333090627` succeeded for Rust tests, CLI + numeric map export checks, desktop UI and optimized ARM64 APK. Extracted `map-studio-ux-preview.apk` from the artifact and ZIP-integrity-checked its Android manifest, arm64 `libmap_studio.so`, and JAR signature: 3,649,898 bytes (3.48 MiB), SHA-256 `953a52df95734e4f0acbdf1958ab62de02a90f4ad31457dd2465cec53d6d288e`. The install package is now `dev.despairarc.mapstudio.uxpreview` (**Map Studio UX Preview**), independent of the older Preview and its saved projects. **No physical-device test of v0.6 gestures or actual GBA emulator verification** was performed in this session. Game runtime, GitHub live collaboration and full tileset breadth remain future work. No main game-engine source changed.
